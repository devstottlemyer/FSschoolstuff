# WordPress Deployment and Configuration Instructions

## Step 1: Grant Directory Permissions to the WordPress User
Change ownership of the web directory files to the WordPress user you created.

```bash
sudo chown $USER:$USER /var/www/html/*
```

The asterisk (`*`) targets **all files and subdirectories** within the specified path.

---

## Step 2: Delete Files from the Directory
After changing ownership, delete all files and subdirectories from the website directory.

Directory:
```
/var/www/html/
```

You previously created a `test.php` file in this directory.  
This file **must be deleted**, or WordPress will not clone correctly.

```bash
sudo rm /var/www/html/*
```

---

## Step 3: Verify Deleted Files and Subdirectories
Check the directory to confirm that it is empty.

```bash
cd /var/www/html/
ls -la
```

No files or directories should be displayed.

---

## Step 4: Clone the WordPress Repository
Clone the latest version of WordPress from the official GitHub repository.

```bash
sudo git clone https://github.com/WordPress/WordPress /var/www/html/
```

---

## Step 5: Verify the WordPress Installation
Confirm that the WordPress files were installed successfully.

```bash
sudo ls -la /var/www/html
```

---

## Step 6: Verify File Permissions
Check the permissions of files and subdirectories in the WordPress installation directory.

```bash
sudo ls -ls /var/www/html
```

---

## Step 7: Edit Ownership of the WordPress Directory Contents
Change ownership of **all files and subdirectories** to the Apache user.

```bash
sudo chown -R www-data:www-data /var/www/html/*
```

---

## Step 8: Edit Ownership of the WordPress Installation Directory
Set ownership of the **directory itself** to the Apache user.

This step is **not a repeat** of Step 7. Apache requires separate permissions for directories and their contents.

```bash
sudo chown www-data:www-data /var/www/html/
```

---

## Step 9: Edit the Apache Configuration File
WordPress does not directly use Apache override directives, but `.htaccess` files can provide additional security.

Enable overrides for the `/var/www` path.

Open the Apache configuration file:

```bash
sudo nano /etc/apache2/apache2.conf
```

Find the section:

```
<Directory /var/www/>
```

Locate the line:

```
AllowOverride None
```

This should appear around **lines 170–173**.

Change it to:

```
AllowOverride ALL
```

Save and exit the file.

---

## Step 10: Create a `.htaccess` File
Create a `.htaccess` file inside the `.git` directory to prevent unauthorized access.

```bash
sudo nano /var/www/html/.git/.htaccess
```

Insert the following configuration:

```
order deny, allow
deny from all
```

Save the file.

---

## Step 11: Restart the Apache Service
Restart Apache to apply the configuration changes.

```bash
sudo service apache2 restart
```
