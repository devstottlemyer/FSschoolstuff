# Securing WordPress File Permissions

## Overview

The permissions shown in screenshots or examples should be treated as **guidelines rather than exact values**.  

Proper permission configuration requires applying the **Linux access control principles learned in Computer Operating Systems**, ensuring that files and directories are protected from unauthorized access while still allowing required services (such as the web server) to function correctly.

This exercise demonstrates how to secure the **WordPress web directory** by adjusting directory and file permissions.

---

# File Permission Configuration

## Step 1: Navigate to the WordPress Directory

Navigate to the WordPress root directory and list all files and directories along with their permissions.

```bash
cd /var/www/html/ && ls -la
```

### Command Explanation

| Command | Purpose |
|------|------|
| `cd /var/www/html/` | Changes directory to the WordPress web root |
| `ls -la` | Lists all files with detailed permissions |
| `&&` | Executes the second command only if the first command succeeds |

This step allows you to review the **existing permissions** and identify any potentially insecure settings.

---

## Step 2: Configure Secure Permissions

Apply more restrictive permissions to directories and files within the WordPress directory.

### Set Directory Permissions

```bash
sudo find /var/www/html/* -type d -exec chmod 750 {} \;
```

### Set File Permissions

```bash
sudo find /var/www/html/* -type f -exec chmod 640 {} \;
```

### Command Breakdown

| Option | Description |
|------|-------------|
| `find` | Searches for files and directories within the specified path |
| `-type d` | Targets directories |
| `-type f` | Targets files |
| `chmod` | Modifies file permissions |

### Permission Levels

| Permission | Owner | Group | Others |
|-----------|------|------|------|
| **750 (directories)** | Read, Write, Execute | Read, Execute | No Access |
| **640 (files)** | Read, Write | Read | No Access |

These permissions help prevent unauthorized users from viewing or modifying WordPress files.

---

## Step 3: Validate the Permission Changes

Test the new directory permissions by attempting to access protected directories **as a regular user (not root)**.

Use These:

```bash
cd wp-admin
cd wp-content
cd wp-includes
```

If permissions are configured correctly, the system should return:

```
Permission denied
```

This confirms that unauthorized users cannot access restricted directories.

---

# Result

After completing these steps:

- WordPress directory permissions are more secure
- Unauthorized users cannot access sensitive files
- Access is limited to appropriate system users and services
